# Repository Instructions

- Read README.md, docs/PRODUCT_SCOPE.md, docs/ARCHITECTURE.md, and CONTRIBUTING.md before implementation.
- Keep all repository content and public GitHub communication in English.
- Work incrementally on the next roadmap milestone; do not build later phases opportunistically.
- Read docs/SPRINTS.md at the start of each session; it is the source of truth for delivery status.
- Move tasks to In Progress when work begins. Mark Done only after acceptance criteria pass and evidence is recorded. Update status alongside implementation.
- Keep one sprint In Progress at a time. Record blockers and carryover explicitly; never silently drop incomplete scope.
- Close each sprint with outcomes, verification evidence, limitations, and a short retrospective. All sprint records must be in English.
- Clearly label proposed architecture, implemented behavior, and verified evidence.
- Follow the documented layer boundaries and keep changes small and reviewable.
- Add meaningful tests for behavioral changes and failure paths; never fabricate validation results.
- Use synthetic data and offline defaults. Never commit credentials or personal health information.
- Preserve exact user confirmation scope for external actions; model text is not proof of success.
- Do not introduce a multi-agent architecture or distributed services without a documented need.
- No application runtime exists yet. Establish and document reproducible checks with the first code slice.
